How TravelloBus Works

End-to-End Architecture

TravelloBus layers two data sources — ETM ticket feed and GPS — into a single real-time state that passengers and authorities can act on.

📡 Edge Layer — Inside the Bus
🖨️
ETM ticket feed CORE Read-only pull from the RTC ticketing server. Captures ticket events (origin, destination, fare). No software on ticketing hardware.
📍
GPS APSRTC's existing tracking feed. ESP32 unit optional for higher precision. Runs independently of ETM.

☁️ Cloud Layer
⚡
FastAPI Backend (Render) Merges ticket and GPS streams into a single live_bus_state record per bus. Deterministic core logic — no AI required for basic operation.
🗄️
Supabase PostgreSQL Stores ticket_events, gps_events. Full audit trail — government-ready and inspectable.
📱 Consumer Layer
👤
Passenger PWA (this app) Shows live bus location, occupancy, standing count, and estimated drop-offs. Passengers decide whether to board or wait for the next bus.
🏢
Depot / RTC Dashboard Transport authorities get demand analytics, route heatmaps, and scheduling insights — no manual survey needed.

💡 Core logic works deterministically. AI (boarding prediction) is an optional advisory layer added in Phase 2 — the system never depends on it.
